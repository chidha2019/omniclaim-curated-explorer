# ADR-001: Read-only serving boundary and role isolation

Status: accepted for this implementation.

Use one React application and one FastAPI service over published serving views. Keep transformation ownership in the lakehouse repository. Expose no claim intake, update, adjudication or payment execution routes. Keep customer-currency, product-snapshot-currency and claim grains explicit.

Use issuer-verified tenant/group claims to select allowlisted Snowflake roles; disable secondary roles and create a fresh bounded session per query. This avoids cross-tenant pool state, at the cost of connection setup latency. Do not replace it with a shared mutable-role pool without explicit isolation tests.

Add small release-aware wrapper views because current pipeline views do not expose release IDs. Read rows and publication metadata in one statement, bind search values, allowlist sort columns, sign cursors and return 409 on release change. Cap interactive browsing at 10,000 rows.

Keep OpenAPI generated from FastAPI and checked in. Generate TypeScript response types from it and fail CI on drift. Express remaining semantic dependencies in the repository evidence map for graph crawling.

Use a configured corporate Gateway API listener and existing observability systems; do not provision an unrelated cloud platform or additional business database in this app repository.
